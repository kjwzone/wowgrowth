## 2. 서비스 개요

와우그로스 플랫폼은 중소기업의 기업정보, 재무정보, 인증정보, 특허정보 등을 기반으로 정부지원사업 공고 데이터를 분석하여 기업별 맞춤 지원사업을 추천하고, 기업진단 보고서와 사업계획서 초안을 자동 생성하는 AI 기반 SaaS 플랫폼이다.

초기 MVP는 전체 자동화 플랫폼을 한 번에 개발하지 않고, 핵심 가치 검증에 필요한 기능만 우선 구현한다.

초기 MVP의 핵심 흐름은 다음과 같다.

```text
회원가입/로그인
→ 기업정보 등록
→ 정부지원사업 공고 조회
→ 기업정보 기반 추천사업 확인
→ AI 공고 요약 및 메타데이터 추출
→ 기업진단 보고서 초안 생성
→ 사업계획서 초안 자동작성
→ 관리자 검수
```

## 3. 문제 정의

중소기업은 정부지원사업에 관심이 많지만 다음과 같은 문제를 겪고 있다.

| 문제           | 설명                                           |
| ------------ | -------------------------------------------- |
| 공고 정보 분산     | 기업마당, K-Startup, IRIS 등 여러 사이트에 공고가 흩어져 있음   |
| 공고문 해석 어려움   | HWP/PDF 공고문이 길고 복잡하여 핵심 조건 파악이 어려움           |
| 기업별 맞춤 추천 부족 | 기존 플랫폼은 공고 목록 제공 중심이며 기업별 정밀 추천이 약함          |
| 신청 준비 부족     | 기업이 어떤 인증, 재무지표, 특허, 연구소 요건을 보완해야 하는지 알기 어려움 |
| 사업계획서 작성 부담  | 정부지원사업 신청을 위한 사업계획서 작성에 많은 시간과 전문성이 필요함      |
| 컨설팅 품질 편차    | 컨설턴트 역량에 따라 진단과 작성 품질이 달라짐                   |

## 4. 서비스 목표

## 4.1 최종 서비스 목표

와우그로스 플랫폼의 최종 목표는 다음과 같다.

1. 정부지원사업 공고 데이터 수집
2. HWP/PDF 원문 추출 및 가공
3. AI 기반 공고 요약 및 분류
4. 기업정보 기반 맞춤형 지원사업 추천
5. AI 기업진단 보고서 생성
6. 사업계획서 초안 자동작성
7. 관리자 검수 및 품질관리
8. SaaS 기반 웹/앱 서비스 제공

## 4.2 MVP 목표

초기 MVP는 다음 기능을 구현하는 것을 목표로 한다.

| 구분  | MVP 목표                     |
| --- | -------------------------- |
| 사용자 | 회원가입, 로그인, 기업정보 등록         |
| 공고  | 관리자 수동 등록, 지원사업 목록 및 상세 조회 |
| 매칭  | 기업정보 기반 기본 추천              |
| AI  | 공고 요약, 메타데이터 추출            |
| 보고서 | 기업진단 보고서 초안 생성             |
| 계획서 | 사업계획서 초안 자동작성              |
| 검수  | 관리자 검수 상태 관리               |
| 배포  | Vercel 기반 웹 배포             |

## 5. MVP 개발 원칙

| 원칙          | 내용                                               |
| ----------- | ------------------------------------------------ |
| MVP 우선      | 전체 자동화보다 핵심 흐름을 먼저 작동시킨다                         |
| 수동 등록 우선    | 자동 크롤링보다 관리자 수동 등록과 CSV 업로드를 먼저 구현한다             |
| 규칙 기반 추천 선행 | AI 추천보다 지역, 업력, 업종, 매출 기준의 기본 추천을 먼저 구현한다        |
| 단일 에이전트 방식  | 초기 MVP에서는 하나의 AI API 구조로 공고 요약, 진단, 계획서 초안을 처리한다 |
| 관리자 검수 필수   | AI 결과는 바로 확정하지 않고 관리자 검수 상태를 둔다                  |
| 확장 가능 구조    | 추후 멀티 에이전트, 자동 크롤링, 결제, 알림 기능으로 확장 가능하게 설계한다     |

## 6. 사용자 유형

| 사용자 유형  | 설명                        | 주요 기능                            |
| ------- | ------------------------- | -------------------------------- |
| 비회원     | 서비스를 처음 방문한 사용자           | 랜딩페이지, 회원가입, 로그인                 |
| 기업회원    | 정부지원사업을 찾는 중소기업 사용자       | 기업정보 등록, 추천사업 조회, 보고서 생성         |
| 예비창업자   | 창업지원사업을 찾는 개인 또는 팀        | 기업/창업정보 등록, 추천사업 조회, 사업계획서 초안 생성 |
| 컨설턴트    | 여러 기업을 관리하는 전문가           | 기업별 추천사업 확인, 보고서 검토              |
| 관리자     | 와우그로스 운영자                 | 공고 등록, AI 결과 검수, 사용자 관리          |
| 전문가 검수자 | 진단보고서와 사업계획서 품질을 검토하는 사용자 | 보고서 검수, 계획서 검수                   |

| 권한       | 설명      |
| -------- | ------- |
| user     | 일반 기업회원 |
| admin    | 관리자     |
| reviewer | 전문가 검수자 |

## 7. 핵심 사용자 시나리오

## 7.1 기업회원 시나리오

```text
1. 사용자가 회원가입을 한다.
2. 로그인 후 대시보드로 이동한다.
3. 기업정보를 입력한다.
4. 지원사업 목록을 확인한다.
5. 추천사업 목록에서 자사에 맞는 공고를 확인한다.
6. 추천사유와 보완사항을 확인한다.
7. 기업진단 보고서 초안을 생성한다.
8. 특정 추천사업을 선택해 사업계획서 초안을 생성한다.
9. 생성된 초안의 검수 상태를 확인한다.
```

## 7.2 관리자 시나리오

```text
1. 관리자가 로그인한다.
2. 관리자 대시보드로 이동한다.
3. 정부지원사업 공고를 수동 등록한다.
4. 공고 원문 또는 요약문을 입력한다.
5. AI 요약 및 메타데이터 추출을 실행한다.
6. AI 결과를 검수하고 수정한다.
7. 공고를 승인 상태로 변경한다.
8. 기업별 추천 결과와 보고서 생성 결과를 확인한다.
```

## 7.3 전문가 검수자 시나리오

```text
1. 전문가 검수자가 로그인한다.
2. 검수 대기 중인 기업진단 보고서를 확인한다.
3. AI가 작성한 보고서 초안을 검토한다.
4. 오류, 과장 표현, 근거 부족 내용을 수정한다.
5. 승인 또는 반려 상태를 지정한다.
6. 사업계획서 초안도 동일한 방식으로 검수한다.
```

## 20. 단일 에이전트 운영 명세 (Next.js + Supabase + OpenAI 기준)

단일 에이전트는 유지하되, 작업 목적별 프롬프트를 분리해 안정성을 확보한다.

## 20.1 task_type 정의

| task_type                | 목적                | 출력 |
| ------------------------ | ----------------- | -- |
| announcement_summary     | 공고 핵심 요약          | JSON |
| announcement_metadata    | 공고 구조화 메타데이터 추출   | JSON |
| recommendation_reasoning | 추천사유/보완사항 생성      | JSON |
| diagnosis_draft          | 기업진단 보고서 초안 생성    | JSON |
| plan_draft               | 사업계획서 섹션별 초안 생성   | JSON |

## 20.2 필수 운영 규칙

1. 서버(Next.js API Route 또는 Server Action)에서만 OpenAI API를 호출한다.
2. 모든 AI 출력은 JSON schema 검증 후 저장한다.
3. 검증 실패 시 1회 재시도 후 failed 상태로 저장하고 관리자 확인 대상으로 전환한다.
4. 결과 데이터에는 model, prompt_version, task_type, created_at을 함께 저장한다.
5. 사용자 화면은 AI 작업 상태(queued, running, succeeded, failed)를 표시한다.

## 21. 2단계 화면맵 작성 체크리스트

화면맵은 도메인별로 "목록/상세/입력(생성·수정)/상태·에러"를 모두 포함해야 한다.

## 21.1 사용자 화면 (필수)

| 도메인 | 목록 | 상세 | 입력 | 상태/에러 |
| ---- | -- | -- | -- | ----- |
| 인증 | 로그인 | - | 회원가입 | 권한없음/인증실패 |
| 기업정보 | 내 기업정보 | 기업정보 상세 | 등록/수정 | 저장실패/유효성오류 |
| 공고 | 공고 목록 | 공고 상세 | - | 검색결과 없음 |
| 추천 | 추천 목록 | 추천 상세(사유/보완) | - | 생성중/생성실패 |
| AI 결과 | 요약 결과 목록 | 요약/메타 상세 | - | queued/running/failed |

## 21.2 관리자/검수자 화면 (필수)

| 도메인 | 목록 | 상세 | 입력 | 상태/에러 |
| ---- | -- | -- | -- | ----- |
| 공고 관리 | 공고 관리 목록 | 공고 상세 | 등록/수정 | 저장실패 |
| AI 검수 | 검수 대기 목록 | 검수 상세 | 승인/반려 처리 | 충돌/권한오류 |
| 사용자 관리 | 사용자 목록 | 사용자 상세 | 권한 변경 | 변경실패 |
| 운영 모니터링 | 작업 상태 목록 | 작업 로그 상세 | 재시도 | API 실패/타임아웃 |

## 21.3 화면맵 산출물 기준

1. 각 화면은 경로, 접근 권한, 진입/이탈 조건을 포함한다.
2. 각 상세 화면은 "데이터 소스 테이블"을 명시한다.
3. 각 상태 화면은 성공/실패/빈 상태를 분리한다.
4. AI 관련 화면은 생성요청 시점과 결과확정 시점을 분리한다.

## 22. 기술 스택 정합 요구사항 (Next.js + Supabase + OpenAI)

## 22.1 Next.js

1. 인증/권한 체크는 서버 기준으로 강제한다.
2. 민감 데이터 조회는 서버 경유 방식으로 처리한다.
3. AI 요청은 비동기 작업으로 처리하고 폴링 또는 재조회 UX를 제공한다.

## 22.2 Supabase

1. profiles, companies, matching_results, review_logs에 RLS 정책을 필수 적용한다.
2. user는 본인 기업 데이터만 조회/수정 가능해야 한다.
3. admin/reviewer는 검수 대상 데이터 접근 권한을 분리한다.

## 22.3 OpenAI API

1. task_type별 프롬프트 템플릿과 JSON schema를 분리 관리한다.
2. 타임아웃, 재시도, rate limit 대응 정책을 구현 전 명세한다.
3. 프롬프트와 출력에는 개인정보/민감정보 최소화 원칙을 적용한다.
